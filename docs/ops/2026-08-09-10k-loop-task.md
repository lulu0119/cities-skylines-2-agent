## 构建与部署

先按改动所在的 seam 选择最小验证路径：

| 改动 | 游戏运行时命令 | 完成标准 |
| --- | --- | --- |
| `Mod/CS2MCP/RequestHandlers*.cs`、tool catalog、内置 gameplay skills | `cd Mod/HotReload && dotnet build` | 下一次 bridge 请求出现新的 `hot-reloaded request handlers` MVID；`Cities2.exe` PID 不变；`FileSystem.log` 无新增 watcher reload |
| UI TSX/CSS | `cd Mod/UI && npm run dev` | Gameface 只 reload 一次，聊天/session 状态保留 |
| `Mod.cs`、`BridgeSystem`、`BridgeToolSystem`、`AgentLoop`、设置、Cohtml binding contract、ECS system 注册、热更新 interface | 干净退出游戏后 `cd Mod && dotnet build` | 0 error，重新启动后 `OnLoad` 正常 |

`Mod/HotReload` 把 payload、catalog 和 skills 部署到
`<runtime root>\CitiesSkylines2Agent\hot-reload`，位于 watched `Mods` 目录之外。
handler payload 保留最后一个有效 adapter；坏 payload 不应打断当前城市。Mono 不能卸载
主 AppDomain 内的旧程序集，因此每次游戏会话最多热换 32 次，达到上限后干净重启。
**每次执行主项目 `cd Mod && dotnet build` 后，都必须紧接着执行
`cd Mod/HotReload && dotnet build`，再启动或继续 handler 热更新循环。** 主项目的
ILRepack 会改变宿主程序集标识；沿用旧 payload 会触发依赖失配，只能回退到最后一个
有效 adapter。
完整约束与长期架构见
[`docs/research/2026-08-10-cs2-mod-hot-reload.md`](../research/2026-08-10-cs2-mod-hot-reload.md)。

正式合并/发布前仍必须关闭游戏执行一次 `cd Mod && dotnet build`，并从冷启动验证
生产内置 adapter；开发 payload 不能代替打包验收。

## 循环与验收

循环：启动 → 观察一轮/多轮 agent 行为 → 从日志定位最大问题 →
最小修改 → 按 seam 热更新或冷启动 → 在同一新城市复现。

当前玩法侧已验证的迭代护栏：

- `zone_area` 可以继续使用通用 `Residential Low` / `Commercial Low` 名称；
  handler 会映射为当前地图主题（例如 NA）。不要直接留下通用住宅/商业 zone
  prefab：它可能有 VacantLot 和需求却没有匹配的 growable，表现为永不生长。
- 道路自身承载水管。道路临街的水泵不需要从建筑中心再拉一段水管；该冗余 stub
  会产生永久 `Pipeline Not Connected`。污水出口和发电设施仍按各自规则连接。
- `city_services.garbage.productionRate` 是每日垃圾**产生量**，不是未处理缺口；
  正值不能生成 problem，也不能据此重复建垃圾设施。以 notifications 中真实的
  `GarbagePilingUp` 为准。
- 普通 `Residential High` 到 Big Town（46,700 XP）才解锁，但
  `Residential LowRent` 在 Grand Village（8,300 XP）已可用。高密需求为正且
  普通高密仍锁定时，优先在新道路临街面铺 LowRent；本轮 78 格在两小时内已有
  62 格 occupied，并把 12 小时增长从约 240 人提高到约 1,000 人。
- `zone_area` 会覆盖半径内已有分区。新分区必须优先使用空白道路临街面；若误刷
  导致 Condemned，先恢复原分区并短暂模拟，不要直接拆除仍有租客的建筑。
- Continuous 模式下 Interrupt 必须同时抑制下一次自动续跑；否则取消当前 turn 后
  会立刻排入新 turn。该语义由 `AgentLoop` 所有，不能下推给 UI 猜测。

验收：`city_overview.population >= 10000`，连续多次 `problems[]` 无
sewage/water/electricity/garbage 的 critical/high，money 不持续为负。

每轮迭代用时间戳记录（launch/observe/diagnose/change/build/relaunch），
最后交一份证据报告：时间线关键片段、人口增长曲线、每次改动的文件与理由、
以及“为什么这次改动不会引发黑屏”（无 Mods 内运行时写入、无每帧 UI 事件、
不阻塞主线程）。
